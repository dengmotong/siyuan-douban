# 数据库字段说明

本插件把数据写入思源的**属性视图（Attribute View）数据库**。首次「保存设置」时，插件会读取你的数据库，**自动补齐**下表中所有缺失的列，并清理重复列。

> ⚠️ 列名必须与下表**完全一致**。若你手动改名（例如把「评分」改成「豆瓣评分」），插件会视为缺失并**再新建一列**。

---

## 一、书籍数据库

主键列：**书名**（首次添加后由插件自动改名）

| 列名 | 思源列类型 | 数据来源 | 备注 |

| 书名 | 主键（block） | 豆瓣标题 | 添加后成为文档标题 |
| 封面 | 资源（mAsset） | 豆瓣封面图 | 自动下载到 `assets/covers/` |
| 副标题 | 文本 | 豆瓣副标题 | |
| 原作名 | 文本 | 豆瓣原作名 | |
| 作者 | 文本 | 豆瓣作者 | 多人以 `, ` 连接 |
| 译者 | 文本 | 豆瓣译者 | |
| 出版社 | 文本 | 豆瓣出版社 | |
| 出版年 | 日期 | 豆瓣出版年 | 仅年份时按 1 月 1 日存储 |
| 出品方 | 文本 | 豆瓣出品方 | |
| 丛书 | 文本 | 豆瓣丛书 | |
| ISBN | 数字 | 豆瓣 / 输入值 | **去重依据** |
| 豆瓣评分 | 数字 | 豆瓣评分 | |
| 评分人数 | 数字 | 豆瓣评价人数 | |
| 定价 | 数字 | 豆瓣定价 | |
| 页数 | 数字 | 豆瓣页数 | |
| 装帧 | 文本 | 豆瓣装帧 | |
| 我的评分 | 单选 | 设置里的「评分等级」 | |
| 书籍分类 | 单选 | 设置里的「书籍分类」 | |
| 阅读状态 | 单选 | 设置里的「阅读状态」 | 默认：想读 / 在读 / 已读 |
| 开始日期 | 日期 | 表单 | |
| 读完日期 | 日期 | 表单 | |
| 书籍简介 | 文本 | 豆瓣内容简介 | |
| 作者介绍 | 文本 | 豆瓣作者简介 | |

**去重 / 清理逻辑**
1. 按 `ISBN` 列比对，已存在则返回「书籍已存在，跳过添加操作」。
2. 自动清理只有 IMDb/ISBN 列有值、书名列为空的**孤立行**。
3. 清理重复列（同名只保留第一个）以及遗留的「单选」列。

## 四、如何创建数据库

1. 在思源里新建一个文档。
2. 输入 `/属性视图`（或 `/数据库`）回车，插入一个属性视图块。
3. 点击属性视图块左上角图标 → `复制` → **复制块 ID**。
4. 打开插件 → `用户设置` → 把 ID 粘贴到对应输入框 → `保存设置`。

保存时会校验：
- `未找到对应的数据库块，请输入数据库视图块ID` → 块 ID 不存在。
- `该块不是有效的属性视图数据库块` → 该块里没有 `data-av-id`，即不是属性视图。

> 只要 ID 正确，**不需要**手动建任何列，插件会自动补齐并排序。

---

## 五、数据库存储位置（排查用）

属性视图的底层数据保存在思源工作空间：

```
工作空间/data/storage/av/{avID}.json
```

插件在把主键列改名为主键名（书名 / 电影名 / 剧名）时会直接读写该文件；若思源没有写文件权限（部分 Docker / 移动端场景）可能失败，此时数据库仍可用，只是主键列名保持原样。
